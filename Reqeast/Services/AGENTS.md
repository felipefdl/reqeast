# Services Layer

Swift services sit between SwiftUI/`ProjectStore` and Rust (UniFFI), CloudKit, Keychain, and disk. Read [`../../AGENTS.md`](../../AGENTS.md) for CKSyncEngine requirements and cross-cutting error rules. Views and stores orchestrate UX; services own side effects, FFI calls, sync queueing, credential storage, and spec import/export pipelines.

## Responsibilities

| Area | Primary files | Role |
|------|---------------|------|
| Rust FFI wrappers | `HttpService`, `TcpService`, `UdpService`, `JqFilterService` | Map Swift models ↔ UniFFI types; offload blocking Rust calls |
| iCloud sync | `CloudSyncService*` | CKSyncEngine lifecycle, record build/decode, conflict LWW |
| Credentials | `KeychainService`, `GitTokenKeychainService` | Request auth (iCloud-synced) vs Git PATs (device-local) |
| Spec pipeline | `SpecImport*`, `SpecSync*`, `SpecExport*`, `SpecSnapshotService` | Parse in Rust; map, merge, persist, sync in Swift |
| Safe user-controlled fetch | `SafeFetchService`, `SafeFetchTrustedHosts` | SSRF-safe Git/spec URL fetch with IP pinning |
| Git auth | `GitOAuthService`, `GitSpecSourceService` (in `GitSourceRef.swift`) | Device OAuth + PAT storage; provider REST fetch |
| Utilities | `EnvironmentVariableService`, `UrlNormalizer`, `SessionPersistenceService`, etc. | Shared non-UI helpers |

Keep files under ~150 lines. Split by extension (`CloudSyncService+SendHandling.swift`) or subfolder (`ImportRequest/`, `Auth/`, `CodeSnippet/`).

## Generated vs Hand-Written Boundaries

**Never edit these** (regenerated by `just build-rust`):

- `Reqeast/Services/reqeast_core.swift` — Swift UniFFI bindings (copied from build output)
- `ReqeastCore/reqeast_core.xcframework/` — universal Rust binary
- `ReqeastCore/Headers/reqeast_coreFFI.h`, `module.modulemap`

**Hand-written Swift** calls into generated types (`HttpClient`, `parseSpec`, `diffSpec`, `ReqeastError`, `jqFilter`, etc.). After any Rust API change: run `just build-rust`, then fix Swift call sites. Do not patch generated files.

## UniFFI Integration

- Rust exposes networking via proc-macro UniFFI (`#[uniffi::export]`, `Record`, `Enum`). No UDL.
- Synchronous FFI blocks the calling executor. Offload with **`@concurrent`** functions (structured concurrency, inherits caller priority). **Do not add new `Task.detached`** — legacy only (`HttpService.send` still uses it; migrate to `@concurrent` when touching that path).
- Pattern (see `JqFilterService`, `SpecImportService.parseSpecOnBackground`, `SpecExportService.exportOnBackground`):

```swift
@concurrent
private static func rustWork(...) async throws -> T {
    try parseSpec(...)  // synchronous UniFFI
}
```

- Map `ReqeastError` → `RequestError` at boundaries. Preserve full error text for developers.

## CloudSyncService Architecture

`@MainActor` singleton (`CloudSyncService.shared`). Started from `ProjectStore` init; **must be alive before background pushes** (see Remote Notifications below).

### File split

| File | Responsibility |
|------|----------------|
| `CloudSyncService.swift` | `start()`, `queueSave`, `queueSaveBatch`, `queueDelete`, `syncChanges`, dirty/oversized tracking |
| `CloudSyncService+Delegate.swift` | `CKSyncEngineDelegate`: events, `nextRecordZoneChangeBatch`, `provideRecord`, account changes |
| `CloudSyncService+FetchHandling.swift` | Remote upserts/deletes, tombstone rejection, zone purge handling, spec asset hydration fallback |
| `CloudSyncService+SendHandling.swift` | Save/delete outcomes, conflict resolution, retry classification |
| `CloudSyncService+Records.swift` | `buildRecord`, LWW `resolveConflict`, `decodeAndApplyUpsert`, SpecDocument CKAsset |
| `CloudSyncService+Migration.swift` | One-shot re-queue of existing local data after CKSyncEngine adoption |

### Data model

- Private CloudKit database, single zone `"Reqeast"`.
- Record name: `"<SyncRecordType>/<UUID>"` (e.g. `Request/…`).
- Payload: JSON in `data` field + top-level `updatedAt` for LWW. `SpecDocument` may attach CKAsset (≤5 MiB) with fingerprint dedup.
- Models conform to `CloudSyncable` (`updatedAt`, `deletedAt`, `syncRecordType`). Always call `touch()` before `queueSave`.
- Soft-delete: `tombstone()` + `DeletionTombstoneStore` blocks ghost resurrection from late remote upserts.
- Scale rule: sync work must be **proportional to changed items**, not total collection size. Use `queueSave` per edit; `queueSaveBatch` for bulk import/sync apply (children before `Project`).

### Delegate flow

1. **Outbound**: CRUD → `queueSave` / `queueDelete` → engine pending changes → `nextRecordZoneChangeBatch` → `provideRecord` (nil + `cancelPendingSave` if item missing/soft-deleted).
2. **Inbound**: `fetchedRecordZoneChanges` → tombstone check → `decodeAndApplyUpsert` → `ProjectStore.applyRemoteUpsert` inside `withRemoteBatch`.
3. **Conflicts** (`serverRecordChanged`): LWW via `updatedAt` on CKRecord fields (ties → server wins). Undecidable → report `cloudConflictUnresolvable`, default server. Local wins → `touchLocalItem` + re-queue save.
4. **State**: `stateUpdate` events persist engine serialization to UserDefaults (`StorageEnvironment.keyPrefix` in debug/tests).

### `syncChanges()`

Foreground / pull-to-refresh / Cmd+R: `sendChanges()` then `fetchChanges()`, coalesced via `isSyncing`. Per-record errors surface through delegate; outer `CKError.partialFailure` suppressed when `partialErrorsByItemID` is populated (`CloudSyncSendHandling.reportableError`).

## CKSyncEngine Remote Notifications — DO NOT REMOVE

CKSyncEngine **requires** Remote Notifications. It registers its own `CKDatabaseSubscription` and handles silent pushes internally. **No `didReceiveRemoteNotification` handler is needed.**

Removing any of these **breaks iCloud sync entirely**:

| Requirement | Location |
|-------------|----------|
| `UIBackgroundModes: remote-notification` | `Reqeast/Info.plist` |
| `aps-environment` + `com.apple.developer.icloud-services` | `Reqeast.entitlements` |
| `registerForRemoteNotifications()` | `ReqeastApp.init()` (macOS + iOS) |
| Eager `_ = ProjectStore.shared` | `ReqeastApp.init()` — ensures `CloudSyncService.start()` before background-launch pushes |

## SafeFetch (SSRF Protection)

`SafeFetchService` fetches user-supplied URLs (Git raw files, public spec URLs). **Not** used for normal HTTP requests (those go through Rust `HttpClient`).

- **HTTPS-only** by default; HTTP allowed only for **user-trusted hosts** (`SafeFetchTrustedHosts`).
- **DNS resolve → validate all IPs** against `IPAddressBlocklist` (RFC1918, loopback, link-local, multicast, etc.). User-trusted hosts may resolve to private IPs (GitHub Enterprise).
- **IP pinning**: rewrite URL host to resolved IP; send original hostname as `Host` header; TLS via `NWConnection` + SNI (`PinnedIPURLProtocol`).
- **Redirects**: manual, max 3 hops; each hop re-validated.
- **Response cap**: 5 MiB streaming limit (`SafeFetchLimits.maxBodyBytes`).
- **Git host allowlist**: built-in (`github.com`, `gitlab.com`, subdomains) + user-added hosts in Settings. `GitOAuthService` and `GitSpecSourceService` enforce the same policy.

Tests inject `FixedTrustedHostPolicy`, `MockURLProtocol`, or `SafeFetchService.shared` override (DEBUG).

## Spec Import (Swift Side)

**Rust owns**: parse, normalize, fingerprint, `diff_spec`. **Swift owns**: mapping, store writes, CloudKit queueing, Rule A merge, Keychain, UI orchestration.

### Pipeline

1. **`SpecImportService.preview`** — detect format (Postman/HAR heuristics), `parseSpec` on background (`@concurrent`), **`SpecImportMapper.map`** → `SpecImportPreview`. No store writes.
2. **`SpecImportService.commit`** — write spec to `Application Support/reqeast/specs/<projectId>/`, apply snapshots (`SpecSnapshotService`), `store.performBulkImport` or `performBulkMerge`, then `CloudSyncService.queueSaveBatch`.
3. **`SpecSyncService`** — linked-spec sync: Rust `diff_spec`, review UI selections, **Rule A apply**, disk write, `queueSaveBatch` (affected requests only).
4. **`SpecExportService` / `SpecExportMapper`** — project → OpenAPI/Postman via Rust `export_project`; linked projects use **inverted Rule A** review (`SpecExportReviewContext`).

### Rule A (linked-spec merge policy)

Preserves user-owned edits when spec changes. Implemented in `SpecSyncService.mergeRuleA` + `SpecImportMapper` for initial map.

- **Spec wins**: method; url/body unless locally modified (vs `SpecOperationSnapshot` baseline).
- **User wins**: rename (`isRenamed`), auth type + Keychain credentials, headers/params the user added or disabled.
- **Snapshots**: `SpecOperationSnapshot` on disk; `specFieldFingerprint` synced. `hasLocalModifications` drives conflict flags in sync/export review UI.
- **Never** overwrite Keychain credentials during sync apply (`mergeOptions.scaffoldAuth = false`).

### Disk layout

`SpecImportService.specsDirectory(for:)` → `~/Library/Application Support/reqeast/specs/<projectId>/` with `spec.json|yaml`, optional `bundle/`, `fingerprint.txt`. Bookmarks for linked local folders via `SpecBookmarkStore`.

## RequestError Propagation

**Never store errors as `String?`.** Use `RequestError` (`kind`, `message`, `localizedTitle`, `iconName`).

| Source | Mapping |
|--------|---------|
| Rust `ReqeastError` | `RequestError.from(ReqeastError)` |
| CloudKit | `RequestError.fromCloudKit(CKError)` → typed kinds (`cloudQuotaExceeded`, `cloudNotAuthenticated`, …) |
| SafeFetch | `SafeFetchError` → surface in import UI; convert to `RequestError` when shown in shared error chrome |
| Git OAuth | `GitOAuthError` / `GitSpecSourceError` — typed enums with `LocalizedError` |
| HTTP send | `HttpService` returns `Result<…, Error>`; session stores map to `RequestError` for display |

Cloud sync errors accumulate in `CloudSyncState` (`syncState.report`). Views use `.textSelection(.enabled)` on error text.

## Git OAuth and Enterprise Keychain Patterns

Two keychain services — **do not conflate**:

| Service | `kSecAttrSynchronizable` | Service ID | Stores |
|---------|--------------------------|------------|--------|
| `KeychainService` | `true` (iCloud Keychain) | `com.reqeast.credentials` | Per-request HTTP auth (bearer, basic, API key, `HttpAuthData`) |
| `GitTokenKeychainService` | **`false`** (device-only) | `com.reqeast.git.pat` | GitHub/GitLab PATs from OAuth device flow or manual entry |

- **Token key**: `"\(provider.rawValue):\(owner)"` (e.g. `github:acme`). Stored in `GitSourceRef.tokenKey` metadata (synced via CloudKit on `SpecLink`); **token bytes never sync**.
- **`GitOAuthService`**: GitHub device authorization grant; host must pass `SafeFetchTrustedHosts.isAllowedForGitFetch`. Enterprise hosts use custom base URL from account `host`.
- **`GitOAuthAccountRegistry`**: UserDefaults list of connected accounts (not secret).
- **`DataResetService`**: clears both keychains + `GitOAuthAccountRegistry` on reset-all-data.
- **Fetch path**: `GitSpecSourceService` uses `SafeFetchService` + PAT from `GitTokenKeychainService` for private provider API/raw URLs.

## Other Services (Quick Reference)

- **`HttpService`**: builds `HttpRequestConfig`, applies Swift-side auth helpers (`JwtAuthService`, `HawkAuthService`, `AwsSignatureService`, `AkamaiEdgeGridService`), calls Rust `HttpClient.send`.
- **`SessionPersistenceService`**: batched JSON for TCP/UDP/HTTP session state under Application Support.
- **`DataResetService`**: coordinated wipe of store, keychains, sync state, tombstones, spec dirs.
- **`MCPExportService`** (macOS only): debounced JSON export for MCP integration.
- **`ImportRequest/`**: curl/httpie/wget import mappers (separate from OpenAPI spec import).
- **`CodeSnippet/`**: language generators from resolved HTTP requests (no Rust).
